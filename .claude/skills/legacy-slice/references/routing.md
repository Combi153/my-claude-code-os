# 라우팅 정본 — 증상에서 담당으로

빨간불이 켜졌을 때만 읽는다. 오케스트레이터가 **원인을 정하고 나서** 파견한다. 이 파일이 두 표의 정본이고, 다른 스킬은 사본을 두지 않고 여기를 가리킨다 — v2 에서 진단표가 네 곳에 복사되어 이미 갈라져 있었다.

## 기계 검사(L2)의 증상 — `slicecheck` 단계 3~6

| 증상 | 원인 | 담당 |
|---|---|---|
| 예상 밖 불일치, 값이 다름 | 규칙 누락·오역 (`diff_keys` 로 원장 행 지목) | builder |
| 예상 밖 불일치, 그 규칙이 원장에 없음 | 새 규칙 | Phase 2 (새 ID) |
| 예상 밖 불일치, 모양(키·타입·빈 값)이 다름 | 어댑터 반환 형태 | builder |
| `의도수정` 인데 예상 밖으로 잡힘 | `ignore.json` 누락 | builder |
| 로그가 비어 있음 | 토글이 PHP 에 도달하지 않음 / 로그 경로 | builder + `local-stack` 되읽기 |
| migrated 골든 차이가 `의도수정` 으로 설명 안 됨 | 화면 규칙 누락 또는 어댑터 | builder |
| **독 주입에서 화면이 바뀜** | **화면 값이 여전히 레거시에서 온다 — 이관이 안 됐다** | Phase 3 (배치 재검토) 또는 builder |
| `migrated` 에서 레거시 본문 실행 줄이 0 이 아님 | 래퍼가 레거시를 여전히 부른다 | builder |
| 캡처가 `logged_out`·`error_page` 플래그 | 세션 만료·스택 이상 — 비교 자체가 무효 | 오케스트레이터 (환경 먼저) |
| `slicecheck` exit 3 | **검사할 수 없었다.** 통과가 아니다 | 오케스트레이터 (설정·도구 부재부터) |

**루프를 오라클을 약하게 만들어 닫지 마라.** corpus 항목을 지우거나 `mode` 를 `full` 에서 `structure` 로 낮추거나 `ignore.json` 에 키를 더 넣으면 불일치는 사라진다. 사라진 것은 불일치이지 원인이 아니다. `ignore.json` 의 모든 항목은 잡음 바닥 측정(`origin: noise`)이거나 **승인된 원장 행**을 가리켜야 하고, 가리키지 못하는 항목은 승인이 아니라 은폐다.

## 감사 판정(L3) — 어휘는 여섯

**정본은 `.claude/agents/domain-boundary-auditor.md` 하나**다. 아래 표에 없는 어휘가 돌아오면 그것은 감사 결과가 아니라 두 파일이 갈라졌다는 신호다 — 라우팅하지 말고 그 사실을 보고한다. `selftest.py` 가 이 두 목록을 대조한다.

| 판정 | 되돌아갈 곳 | 게이트 |
|---|---|---|
| `PASS` | Phase 7 | — |
| `템플릿 규칙 잔존` | Phase 1 | 가드·이동 계획이 바뀌면 G1 다시 |
| `계층 오배치` | Phase 4 | 설계가 바뀌면 Phase 3 + G2 다시 |
| `잔류합의 근거 소멸` | Phase 3 | G2 다시 |
| `무방비` (`불가`·`의도수정` 행에 단위 테스트 없음) | Phase 4 | — |
| `새로 발견된 규칙` | Phase 2 (새 ID) | 설계가 바뀌면 Phase 3 + G2 |

재진입은 그 아래 Phase 를 다시 돈다. **감사만 다시 하는 것은 `boundary-audit` 모드 A 로 싸게 하고** 전체 재진입과 구별한다 — v2 는 이 싼 경로를 만들어 두고 오케스트레이터가 쓰지 않았다.

## 캡처 라벨 — 이름은 하나

| 라벨 | 언제 | 만드는 쪽 |
|---|---|---|
| `before` / `after` | Phase 1 의 추출 루프, 회차마다 덮어쓴다 | 추출 담당 |
| `baseline` | **추출이 끝난 뒤의 기준선.** `migrated` 와 비교하는 상대가 이것이다 | 추출 담당 (L0 가 닫힐 때 `after` 를 복사) |
| `dual` | `slicecheck --stage 3` | `slicecheck` |
| `migrated` | `slicecheck --stage 4` | `slicecheck` |
| `poison` | `slicecheck --stage 5` | `slicecheck` |

v2 에서 라벨이 세 어휘로 갈라져 있었고 `captures/legacy` 는 만드는 단계가 없는 채 비교 입력으로 쓰였다. **`baseline` 을 만드는 단계는 L0 의 종료이고, 그것이 유일한 기준선이다.**
