# 행위 원장 — 조인 키의 계약

원장은 이 파이프라인의 **조인 키**다. 두 오라클이 여기서 만나고 도메인 문서가 여기서 생성된다. 그래서 한 문장이 전체를 지배한다.

> **원장에 없는 것은 어느 단계도 보지 못한다 — 설계 자신의 의심도 마찬가지다.**

설계서에 "이건 검증 안 된 추정이다"라고 적는 것으로는 부족하다. 그 의심이 관찰 가능한 **행**이 되지 않으면 아래 단계는 그것을 지지 않고, 실제로 그렇게 통과한 슬라이스가 있었다.

## 열과 소유권

v3 부터 원장은 **JSONL 한 줄이 규칙 하나**다. 정본은 `legacy-slice/references/ledger-format.md` 이고, 여기서는 **어기면 파이프라인이 깨지는 것**만 적는다.

```json
{"id":"R-07","rule":"<업무 문장 하나>","class":"도메인","src":["<file>:120-134"],
 "range":"120-134","obs":"대기","state":"대기","approve":null,"note":""}
```

- **ID 는 append-only.** 한 번 부여하면 바뀌지 않고 재사용하지도 않는다 — 다른 산출물이 이 ID 로 이 행을 가리킨다.
- **열마다 주인이 하나다.** `rule`·`class`·`src`·`range` 는 분석가, `obs` 는 관찰 담당(또는 커버리지 측정), `state` 는 builder, `approve` 는 사람, `note` 는 누구나. 자기 열이 아닌 곳을 고치지 않는다 — 고치면 그 열의 주인이 다음 단계에서 덮어쓰고, 덮어쓴 사실은 아무 데도 남지 않는다. **JSONL 인 이유가 이것이다**: 검사기가 전후를 비교해 역할 밖의 열이 바뀌었는지 셀 수 있고, 모델이 Markdown 표보다 덜 덮어쓴다.
- **`rule` 은 구현이 아니라 규칙으로 쓴다.** 구현으로 쓰면 리팩터링 한 번에 거짓이 되고 기획자가 읽을 수 없다.

## 값 어휘 — 새로 만들지 않는다

어휘 밖의 값은 그것을 읽는 도구와 감사에게 **없는 값**이다.

- `obs`: `이중실행:<experiment>` · `골든:<corpus-id>` · `단위:<테스트 심볼>` · `불가:<이유>` · `제외:의도수정` · `대기`
- `state`: `이관됨:<심볼>` · `의도수정:<심볼>` · `잔류합의:<이유>` · `대기` · `미이관`
- `approve`: `null` 또는 `{"who":"<승인자>","when":"YYYY-MM-DD"}`

`불가`와 `의도수정`은 **승인이 붙은 예외**다. 이유 없이 쓰지 않고, `approve` 없이 쓰지 않는다 — v2 에서는 승인자와 일자를 `이관` 값 안에 괄호로 넣었고 그 형태가 정본 포맷과 갈라져 있었다. 이제 승인은 자기 열이다. 이 두 값이 붙은 행은 단위 테스트로 받쳐져야 한다 — 받쳐지지 않은 예외는 감사에서 `무방비`로 잡힌다.

## 표 밖의 세 절

- **`fixture`** — 행 ID 마다 "이 규칙을 관찰하려면 어떤 입력·데이터가 있어야 하는가". 분석가가 쓰고 코퍼스 담당이 읽어 코퍼스로 옮긴다. 여기 없으면 그 규칙은 영원히 `대기` 다.
- **커버리지** — v3 에서는 별도 절이 아니라 각 행의 `range` 다. 종료 조건은 **함수 본문의 모든 문장 범위가 어떤 행의 `range` 에 덮이는 것**이고 그것은 세어진다. `스왑 위험`(제외한 호출자, 같은 함수를 다른 의미로 쓰는 호출부, 배선 미확인 지점)은 `00-seam.md` 에 산다.

## 분류 판정 — 질문 하나

> **전혀 다른 클라이언트(모바일 앱, 배치, 파트너 API)가 같은 데이터를 다룬다면 같은 규칙을 지켜야 하는가?**

그렇다면 **도메인**이다. 페이지 스크립트 안에 있어도, 템플릿 안에 있어도 도메인이다. 아니라면 **화면**이다. 양쪽에 정당하게 있으면 **경계**인데, **경계는 백엔드가 진실일 때만 경계다** — 화면만 검사하고 백엔드가 위반값을 그대로 받으면 그것은 경계가 아니라 아직 안 옮겨진 도메인이다. 값과 규칙이 섞여 있으면 두 행으로 쪼갠다: "한 페이지에 열 개"에서 열은 화면의 결정이고 "페이지 크기를 받는다"는 백엔드의 계약이다.
